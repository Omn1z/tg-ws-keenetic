# Размер, память и скорость

Не сравнивайте размер Windows-сборки (системный Schannel) с Linux-релизом
(статический OpenSSL). Не переносите показатели ARM64 на MIPS без AES-инструкций.
Минимальный размер, максимальная скорость и минимальная RAM — разные параметры;
профили `release` и `speed` позволяют сравнить компромисс на нужном устройстве.

## Размер

После сборки Linux-матрицы скачайте архив своей архитектуры. Сравнивайте отдельно
размер `.tar.gz` для загрузки и распакованного ELF для flash:

```sh
wc -c tgwsproxy
file tgwsproxy
readelf -l tgwsproxy
readelf -d tgwsproxy
```

В статическом ELF не должно быть интерпретатора и `NEEDED`. Релизный workflow
проверяет это автоматически. UPX не используется: выигрыш flash за счёт упаковки
может увеличить память и время старта на слабом роутере.

## RAM на роутере

Найдите PID командой `pidof tgwsproxy`, затем:

```sh
PID=$(pidof tgwsproxy)
awk '/VmRSS|VmHWM|VmSize|Threads/ {print}' /proc/$PID/status
cat /proc/$PID/smaps_rollup 2>/dev/null
```

Снимайте замеры после минуты простоя, при 1/8/16 активных Telegram-соединениях,
при загрузке большого видео и после закрытия клиентов. `smaps_rollup` есть не
на всех ядрах. Память socket buffers ядра не входит в RSS процесса.
Учитывайте число потоков DNS, хранилище сертификатов и память TLS handshake.

По умолчанию: два пользовательских буфера по 16384 байта на соединение,
`max_connections=64`, `pool_size=0`. Дополнительно выделяются состояние AES/TLS,
задачи, ограниченные заголовки и Fake TLS record buffers. Это не обещание
«32 КиБ RSS на клиента». Большие сообщения передаются частями; размер сообщения
не определяет объём буферов прокси.

## Скорость

На одном роутере, с одинаковыми маршрутами DC, TLS, secret и числом клиентов:

1. Выполните три загрузки одного большого файла из Telegram через Python-версию;
   запишите среднюю скорость, загрузку CPU и пик RSS.
2. Повторите с Rust `release` при 4/16/64 КиБ и выключенном пуле.
3. Сравните `speed` с `release`; затем проверьте `pool_size=1` отдельно для времени
   подключения, поскольку прогретый пул в первую очередь сокращает TLS handshake.
4. Между сериями проверяйте, что трафик идёт тем же маршрутом (WS/CF/TCP), а не
   сравниваете разные fallback-серверы или состояние кеша клиента Telegram.

Зафиксируйте модель, CPU, endian, версию ядра, Rust/commit, профиль, размер ELF,
буферы, количество клиентов, RSS/peak RSS, CPU, Мбит/с и время подключения.
До этих измерений утверждать конкретное ускорение относительно Python нельзя.
